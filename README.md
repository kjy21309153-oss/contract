# 조달계약 검토 도우미 — 초심자용 배포 가이드

컴퓨터에 아무것도 설치하지 않고, 브라우저만으로 실제 작동하는 웹페이지를 만드는 순서입니다.
전체 소요 시간: 약 20~30분.

---

## 1단계. Gemini API 키 및 법제처 Open API 키 발급 (5분)

1. **Google Gemini API 키 발급**
   - https://aistudio.google.com 접속 → 구글 계정으로 로그인
   - 좌측 메뉴에서 **Get API key** 클릭
   - **Create API key** 클릭 → 발급된 키를 메모장에 복사해둡니다.
   - *(참고: Gemini Flash 계열 모델은 기본 무료 한도를 제공하며, 카드 등록 없이도 테스트가 가능합니다. 무료 티어의 경우 입력한 내용이 서비스 개선에 활용될 수 있으므로 실제 계약서 원문 등 민감 문서는 공개된 법령·일반 규정 위주로 테스트를 권장합니다. 유료 플랜을 이용할 경우 한도 제약 없이 상위 Performance 모델 등 다른 AI 모델을 선택하여 확장 사용할 수 있습니다.)*

2. **법제처 Open API 신청**
   - 기존 버전에서는 기본 법령 데이터 최신화 방식이 명확하지 않았으나, 현재는 **법제처(law.go.kr) Open API**와 연동되어 법령을 실시간으로 가져옵니다.
   - https://open.law.go.kr 접속 → 회원가입 및 로그인
   - **API 활용신청** 진행 → 발급받은 **사용자 계정(이메일 ID)**을 메모장에 복사해둡니다.

---

## 2단계. GitHub에 코드 올리기 (10분, 설치 없음)

1. https://github.com 접속 → 계정이 없다면 무료 가입
2. 우측 상단 **+** → **New repository** 클릭
3. Repository name에 `contract-ai` 입력 → **Create repository**
4. 방금 만든 저장소 페이지에서 **Add file → Upload files** 클릭
5. 전달받은 파일들(`app.py`, `requirements.txt` 등 필요한 구성 파일)을 **드래그해서 올리기**
6. 하단 **Commit changes** 클릭

이 과정은 전부 웹브라우저 안에서 이루어지며, 컴퓨터에 아무것도 설치하지 않습니다.

---

## 3단계. Streamlit Community Cloud에 배포 및 설정 (5분)

1. https://share.streamlit.io 접속 → **Sign in with GitHub**로 로그인
2. **Create app** 클릭 → **From GitHub** (또는 **From existing repo**) 선택
3. 방금 만든 `contract-ai` 저장소, `app.py` 파일 선택
4. **Advanced settings** 클릭 → **Secrets** 칸에 아래처럼 API 키 입력

   ```toml
   GEMINI_API_KEY = "여기에_1단계에서_복사한_Gemini_키_붙여넣기"
   LAW_API_OC = "여기에_법제처_Open_API_아이디_붙여넣기"

   ```

5. **Deploy** 클릭 → 1~2분 후 `https://XXXX.streamlit.app` 형태의 주소가 생성되면 배포가 완료됩니다.
6. **URL 수정 안내**: 배포 후 앱의 주소를 변경하고 싶다면, Streamlit Cloud의 해당 앱 관리 화면 **Settings** 메뉴에서 URL(App URL)을 원하는 이름으로 수정할 수 있습니다.

## 화면 사용법 및 실습 예시

실제 동작하는 완성된 예시는 **[조달계약 검토 도우미 · Streamlit](https://contract-ewp.streamlit.app/?utm_source=gemini)** URL에서 바로 확인하실 수 있습니다.

* **좌측 상단 (지식창고)**: 법령·규정·표준품셈 PDF/TXT 파일을 올려 지식창고를 구축합니다.
* **법제처 API 연동 현황**: 현재 `공공기관의 운영에 관한 법률`, `국가를 당사자로 하는 계약에 관한 법률`, `중소기업제품 구매촉진 및 판로지원에 관한 법률`, `전기공사업법`, `소프트웨어 진흥법` 등 주요 기본 법령이 법제처 Open API로 연동되어 탑재되어 있습니다.
* 상단의 **🔄 버튼**을 누르면 법제처 API를 통해 최신 공포/시행일자를 대조하고 조문 내용을 최신본으로 자동 교체합니다.


* **좌측 하단 (대화 관리)**: `➕ 새 대화` 버튼 및 대화 이력 목록을 통해 여러 검토 건을 독립적으로 다룰 수 있습니다.
* **가운데 (메인 대화창)**:
* 하단 입력창을 통해 문서를 드래그하여 첨부하거나 질문을 입력하면 지식창고 근거 기반의 검토 의견을 제시합니다.
* **대화 및 질문 삭제**: 입력된 각 질문/답변 우측의 **휴지통(🗑️) 버튼**을 클릭하면 해당 대화 내용을 즉시 삭제하고 메시지 이력을 초기화/정리할 수 있습니다.

## 🛡️ 환각(거짓 내용) 방지 프롬프트 설계 구조

공기업 계약 검토업무에서는 존재하지 않는 조항을 언급하거나 거짓 내용(Hallucination)을 답변하는 것을 엄격히 차단해야 합니다. 이를 위해 `app.py` 내부의 **SYSTEM_INSTRUCTION** 및 검증 로직에 다음과 같은 프롬프팅 방침을 적용했습니다.

1. **엄격한 원문 출처 인용 규칙 (Strict Citation Rules)**
* AI는 미리 구축된 지식창고(참고자료)에 실제로 들어있는 문서 이름과 조·항·호 원문만 인용해야 합니다.
* 문서에 존재하지 않는 발행기관, 제정주체, 또는 AI의 사전 학습 지식에 있던 예전 조문을 임의로 덧붙이거나 지어내는 것을 금지합니다.


2. **최소 15자 원문 직접 인용 (Verbatim Quote Requirement)**
* 특정 조·항·호를 근거로 들 때는 반드시 해당 원문 문구를 **15자 이상 큰따옴표로 인용**하도록 강제합니다.
* 확실치 않은 조항 번호를 무리해서 지어내는 대신, 존재 가능성과 방향을 안내하고 원문 직접 확인을 권고하도록 지침이 설정되어 있습니다.


3. **지식창고 우선 확인 및 외부 검색 단계적 제한 (Gradual Reference Fallback)**
* 1차적으로 지식창고 내 텍스트를 검증하고, 단서를 잡기 위해 구글 검색을 이용하더라도 최종 근거는 지식창고 원문 텍스트로 재확인하여 출력합니다.
* 지식창고에 없는 내용은 공식 출처(law.go.kr 등) 기반 검색 근거임을 명확히 구분 표시합니다.


4. **코드 레벨의 조항 자동 검증 (Code-level Cross-Check)**
* 프롬프트 제약 외에도, AI가 생성한 답변 내 `제O조` 형태의 인용 번호를 추출하여 실제 전달된 지식창고 원문 텍스트에 존재하는지 코드가 2차 검증합니다.
* 원문에 없는 조항 번호가 감지될 경우 경고 문구를 자동으로 덧붙여 사용자가 사실관계를 재확인할 수 있도록 안전장치가 마련되어 있습니다.

## 다음 단계로 확장하려면

* **다수 계정 및 사용자별 개별 운용**: 현 방식은 단일 공유 계정/공통 저장소 방식으로 동작합니다. 다수 사용자가 개인별 독립된 환경으로 운용하려면 SSO 로그인(OAuth) 연동 및 사용자 ID별 데이터베이스(PostgreSQL, Firebase 등) 격리 구조를 추가하거나, 사용자별로 각자의 Gemini API 키를 입력받아 처리하도록 확장해야 합니다.

* **사내망 전용 배포**: 보안이 중요한 실제 계약서 원문을 다루기 위해서는 사내 전용 서버 및 폐쇄망 LLM 인프라로 이전하여 배포하는 것을 권장합니다 (IT/보안 부서 협의 필요).
